# DELTA — Deep Vyas, Lead UI/UX Designer

A portfolio built on one idea: **every project is a before → after.**

The site never shows a screenshot without the number that changed. That constraint
drives the visual identity (the `→` mark, the outcome rail, the mono numerals), the
content model (`Problem → Research → Strategy → Design → Impact`), and the editing
rule stated on the homepage: *if a redesign didn't change a number or give someone
their week back, it isn't here.*

---

## Running it

It's static. Open `index.html`, or serve the folder:

```bash
python3 -m http.server 8777
```

No build step is required to view the site. `build.py` only regenerates the case studies.

## Structure

Everything the site needs lives in this folder — drop new assets into `img/`
and new pages beside `index.html`.

```
index.html          Homepage — hero, work, leadership, process, about, contact
teleconsult.html    ┐
kidneylink.html     │
aip.html            │  Six case studies, generated by build.py.
flintlink.html      │  Do not hand-edit these — edits are overwritten.
pettrackr.html      │
rxagile.html        ┘
build.py            Case-study content + template + generator
css/system.css      Design system: tokens, base, primitives, nav, footer
js/system.js        Behaviour: theme, sticky nav, scroll progress, reveal
img/                62 images — product screens plus 30 process artefacts.
                    Resized to ≤1600px, JPEG q88, ~11 MB total, all lazy
                    except the two above the fold.
cv-deep-vyas-uiux.pdf   Résumé (1 page)
d-logo.svg          Favicon
```

Page-specific CSS stays inline in each page; anything shared lives in `css/system.css`.
That keeps the first paint to one stylesheet request and one script.

## Editing a case study

All six case studies come from the `CASES` list in `build.py`. Change the content there,
then:

```bash
python3 build.py
```

Each case is a dict. Optional keys are skipped cleanly if absent:

| key | what it renders |
|---|---|
| `title`, `sum`, `meta`, `hero`, `stats` | the case hero and outcome bar |
| `problem.finds` | the numbered failure list |
| `problem.signals` | the right-hand research marginalia (optional) |
| `research.methods`, `research.quote` | method cards and the pull quote (quote optional) |
| `strategy.crit` | the numbered success criteria |
| `decisions` | design decisions. A 4th and 5th element `(img, caption)` attaches the artefact that proves it |
| `problem.art` / `research.art` / `strategy.art` / `impact.art` | `(img, caption)` — a chapter-level process artefact |
| `gallery` | screens with captions |
| `impact.outs`, `impact.caveat` | outcome numbers and the honest caveat (caveat optional) |
| `reflection.lessons`, `reflection.diff` | what it taught me / what I'd do differently |

Prev/next links wrap around the list automatically, in list order.

## Process artefacts

Every case study that has them shows the diagram next to the claim it supports: the
before/after IA, the four shell options drawn to scale, the seven-step onboarding beside
the one that replaced it. They come from the project record and keep their original
palette, so they are framed as documents (white card, hairline border, mono caption)
rather than restyled to match the site.

**Two case studies have none.** KidneyLink and RxAgile have no before/after or process
diagrams in the source material — only finished screens. They carry the two strongest
narratives on the site and the weakest visual evidence. Closing that gap means drawing
three diagrams: KidneyLink's chart-versus-sentence comparison and its filter-on-confirm
flow, and RxAgile's five-module dependency sequence.

## Design system

**Type** — `Newsreader` italic for accents only (one word in the hero, client
names, pull quotes) — chosen for its optical-size axis, which keeps it legible
from the 72px headline down to 16px client names, `Inter Tight` for everything structural, `JetBrains Mono` for
labels and every number. Numbers are always mono: that's what makes an outcome read
as measured rather than claimed.

**Colour** — a near-neutral base and exactly one accent (`--accent`), used for the
`→`, for numbers that changed, and for nothing decorative. Dark mode is a token
swap; no component overrides it.

**Selected work** — a typographic index rather than a stack of cards. Six rows in a
ledger on the left; the hovered or keyboard-focused row's screenshot sticks alongside
it on the right, with that project's problem line and leadership note. Below 900px the
same `<figure>` simply falls in beneath its own row — one set of images, no duplication,
and the layout needs no JavaScript. The script only moves the `is-on` / `on` classes.

**Rhythm** — `--sec` between sections, `--gap` inside grids, `--pad` at the page edge.
All fluid via `clamp()`, so there are no layout-only breakpoints — the three media
queries (1080 / 980 / 720 / 480) only change column counts.

**Motion** — reveal-on-enter, the outcome counter, and hover states. Nothing else.
Every animation is behind `prefers-reduced-motion`, and the counter runs from the
*before* value to the *after* value rather than from zero, so no frame shows a
number that was never true.

## Accessibility

- One `<h1>` per page, no heading-level jumps, every image has meaningful alt text
- Skip link, visible `:focus-visible` rings, `aria-current` on the active nav item
- Keyboard-operable theme toggle and copy-email control, with a live-region toast
- Respects `prefers-color-scheme` on first visit, then remembers the choice
- No horizontal overflow from 320px to 1440px

## Performance

No framework, no bundler, no tracking. One stylesheet, one script, one font request.
Everything below the fold is `loading="lazy"`. Images were downscaled to a 1400px
maximum and converted to JPEG q88 — about 5 MB for all 27, of which two load eagerly.

## Content provenance

Every metric, quote and research figure on this site comes from the project record.
Where a number wasn't instrumented, the case study says so in an "honest caveat"
block rather than rounding it into a claim.
